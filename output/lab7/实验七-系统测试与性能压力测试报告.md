# 实验七：系统测试与性能压力测试报告

## 1. 实验目的

本次实验依据“系统测试/软件性能测试”课件要求完成，重点理解并实践以下内容：

1. 理解性能测试、负载测试、压力测试、响应时间、吞吐量、资源利用率、在线用户数和并发用户数等概念。
2. 选择一个已有网站作为被测系统，对其进行系统级功能测试和并发压力测试。
3. 设计可复现的测试场景，记录响应时间、吞吐量、错误率等指标。
4. 使用 JMeter 测试计划或等价自动化脚本完成压力测试，并根据结果进行分析。

## 2. 被测系统

- 系统名称：TOEIC Practice Studio
- 系统类型：Next.js + React + TypeScript Web 应用
- 后端能力：Next.js Route Handlers、本地 SQLite、Prisma
- 测试对象：登录、首页、试卷列表、学习统计、设置页、设置 API、统计 API、试卷 API、整卷作答流程
- 本地被测地址：`http://127.0.0.1:3000`

本系统属于动态 Web 应用，包含页面渲染、认证会话、数据库查询、答题保存、交卷评分和学习统计等功能，适合用于系统测试与性能压力测试。

## 4. 性能测试指标

结合课件内容，本实验主要关注以下指标：

| 指标 | 含义 | 本次记录方式 |
| --- | --- | --- |
| 并发用户数 | 同一时间模拟访问系统的用户数 | `LOAD_USERS=20` |
| 响应时间 | 请求发出到收到响应的耗时 | 平均值、P50、P90、P95、最大值 |

## 7. 结果分析

1. 在 20 个并发用户、800 次核心请求的负载下，系统没有出现失败请求，错误率为 0%，说明当前负载下系统功能稳定。
2. API 请求平均响应时间在 281 ms 到 363 ms 之间，P95 大多在 530 ms 以内，说明后端接口和数据库查询在本地环境中响应较快。
3. 页面请求平均响应时间明显高于 API 请求，尤其登录页平均 3695 ms、P95 4049 ms。这与本次使用 `next dev` 开发服务器有关，开发模式包含编译、调试和热更新开销，不能完全代表生产性能。
4. `/stats` 页面和 `/settings` 页面 P95 高于 3 秒，说明在页面级并发访问时，SSR/页面渲染成本是主要性能关注点。
5. 本次吞吐量为 12.00 requests/s，适合作为本地开发环境下的小规模并发基线。若要评估真实上线能力，应使用 `npm run build && npm run start` 或生产部署环境复测。

## 8. JMeter 复测步骤

已提供 JMeter 测试计划：

- `output/lab7/jmeter-toeic-system-test.jmx`
- `output/lab7/jmeter-users.csv`

图形界面操作步骤：

1. 启动本地应用：

```powershell
npm run dev
```

2. 打开 JMeter。
3. 选择“File -> Open”，导入 `output/lab7/jmeter-toeic-system-test.jmx`。
4. 确认 `CSV Data Set Config` 中的文件路径为 `output/lab7/jmeter-users.csv`。
5. 确认 `Thread Group` 参数：
   - Number of Threads(users)：20
   - Ramp-Up Period：10
   - Loop Count：5
6. 点击运行按钮。
7. 在 `Summary Report` 中查看：
   - Samples
   - Average
   - Min / Max
   - Std. Dev.
   - Error %
   - Throughput
8. 如需导出结果，可查看 `output/lab7/jmeter-summary.jtl`。

命令行运行方式：

```powershell
jmeter -n -t output/lab7/jmeter-toeic-system-test.jmx -l output/lab7/jmeter-summary.jtl -e -o output/lab7/jmeter-report
```

## 11. 实验结论

本次实验完成了 TOEIC Practice Studio 的系统功能测试和并发压力测试。在 20 个虚拟用户、800 次请求的本地负载条件下，系统成功率为 100%，核心业务 smoke 流程通过，说明当前版本具备基本的系统稳定性。

从性能结果看，后端 API 响应较快，页面级响应时间受开发服务器渲染和编译开销影响较明显。后续若要继续优化，可重点在生产模式下复测页面级 P95 响应时间，并结合 CPU、内存、数据库查询日志进一步定位瓶颈。
