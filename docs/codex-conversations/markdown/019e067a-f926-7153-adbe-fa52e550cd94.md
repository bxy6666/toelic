1. 先读规则，再做决策；禁止忽略规则直接改业务代码。
2. 先识别项目类型，再决定技术栈策略、UI 策略、工具策略。
3. 最小改动优先；禁止无关重构、无关优化、顺手改动其他模块。
4. 复用优先；优先复用现有目录、页面、组件、逻辑、样式和环境缓存。
5. 新手可维护优先；保持直观、清晰、低心智负担，禁止过度抽象。
6. 节省 token 优先；先缩小范围，再读取文件，再修改代码。
7. 每次只做一个小目标；改动必须可验证、可回退、可解释。
8. 不回退或覆盖用户已有未提交改动。

## 5. 项目类型判定

在执行任何技术栈相关决策前，必须先判定当前项目类型：

1. Web 前端项目
2. 原生小程序 / 原生 App 项目
3. Node 后端项目
4. Python / Java / Go / 其他后端项目
5. 纯文档 / 规则仓库
6. 混合型项目
7. 未知项目

只有在项目类型明确后，才允许决定：

- 是否接入 shadcn/ui
- 是否需要 Tailwind
- 是否需要前端 UI 组件体系
- 是否运行 build / lint / test
- 是否需要安装或启用条件工具
- 是否需要项目级 UI 覆盖规则

禁止未判定项目类型就默认按 Web 项目处理；禁止把 shadcn/ui 作为所有项目的硬默认；禁止因为全局规则偏向 Web 就强行改造非 Web 项目。

## 6. 环境识别与缓存复用

首次进入一个新项目时，允许执行一次完整环境识别，识别内容包括：

- 技术栈
- 包管理器
- 运行时版本
- Tailwind 状态
- shadcn/ui 状态
- 当前目录结构
- 核心页面 / 核心模块
- 当前 UI 体系
- 可运行脚本（dev / build / lint / test）

首次识别后必须写入项目级 `docs/project-context.md`。若已有有效缓存且不满足重扫条件，则直接复用，不要重复完整扫描。

允许重新完整扫描的条件：

1. 用户明确要求重新扫描
2. 项目根目录变化
3. 锁文件变化
4. 关键配置变化
5. 构建 / lint / test 失败且怀疑缓存失效
6. 引入影响整体架构的重要模块
7. 当前缓存明显失真或与项目实际状态冲突

## 7. UI 技术策略

默认优先使用与当前技术栈兼容的原生 UI / 主流组件体系。

shadcn/ui 仅是条件优先 UI 方案，不是全局硬默认。仅当同时满足以下条件时，才将 shadcn/ui 作为优先 UI 方案：

1. 当前项目属于 React / Next.js / Vite 等兼容 Web 前端项目
2. 项目允许使用 Tailwind，或可最小接入 Tailwind
3. 当前任务确实涉及 UI 页面或组件改造
4. 引入 shadcn/ui 不会造成大规模重构
5. 当前项目不存在更强约束的项目级 UI 规则

不满足条件时，沿用当前项目原生 UI / 现有组件体系，并继续遵守统一、可读、可维护、最小改动原则。

## 10. 自动落地与初始化执行规则

当接手任意项目时，除非用户明确禁止，否则必须先遵守初始化规则；但只有在触发初始化条件时，才显式执行并展示初始化流程，再开始业务任务。

触发初始化条件：

1. 首次进入某个项目，或项目级 `docs/project-context.md` 缺失、明显失真
2. 用户明确要求初始化、重扫环境、输出验收表、检查工具、接入工具、补全规则文件
3. 任务涉及依赖安装 / 卸载、包管理器、运行时、构建链、脚手架、框架接入、UI 技术路线选择
4. 任务需要判断是否适合启用 Context7、ast-grep、shadcn/ui、Tailwind 等条件工具
5. 构建 / 运行 / 调试失败，怀疑缓存或环境结论失效
6. 项目根目录、锁文件、关键配置文件发生变化

若未触发上述条件，则默认静默读取规则、复用缓存、继续当前任务；普通问答、解释、文案、局部小改、已有缓存下的常规开发任务，不主动展示项目类型判定、环境识别摘要、工具检查结果或初始化验收表。

初始化顺序：

1. 读取规则文件
2. 判定项目类型
3. 判断是否需要重扫环境
4. 执行或复用环境识别
5. 检查 `fd`、`ripgrep`
6. 按需评估 Context7、ast-grep、shadcn/ui、Aider
7. 更新或补全规则文件
8. 执行最小验证
9. 在本次实际执行了初始化流程时，输出 PASS / FAIL / SKIP / PARTIAL 验收表

初始化阶段禁止：

- 跳过规则直接改业务代码
- 未识别项目类型就决定 UI 技术路线
- 因工具安装失败而大改项目结构
- 把开发辅助工具写进业务运行时依赖
- 顺手重构业务页面

## 11. 任务执行流程

每次收到新任务时，必须严格遵守：

1. 先读取规则与缓存。
2. 判断是否需要重扫环境；默认不重扫。
3. 输出最小改动计划：目标、涉及文件、依赖变化、风险点、验证方式；仅在当前决策依赖技术路线、环境或工具判断时，才显式说明项目类型或初始化结论。
4. 用省 token 工具定位。
5. 开始小步修改，只动当前目标相关文件。
6. 执行可用验证。
7. 完成后更新 `docs/change-log-ai.md`；若环境或规则变化，再更新 `docs/project-context.md`。

## 12. 依赖安装规则

只允许安装对当前任务确实必要的最小依赖。

默认允许：

- 当前技术栈强相关依赖
- shadcn/ui 所需最小依赖（仅在兼容 Web 项目）
- 搜索 / 文档 / 检索类辅助工具（不进入业务运行时）

默认禁止：

- 与当前项目类型不兼容的 UI 体系
- 白板 / 画布能力
- 大型动画库
- 无关 UI 框架替换
- 与当前任务无关的 agent 框架
- 重量级多 agent 系统
- 为了“以后可能用”预装很多库
